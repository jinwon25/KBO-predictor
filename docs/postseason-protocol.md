# 제출 없는 포스트시즌 평가 프로토콜

정규시즌에서 개발한 예측을 포스트시즌 경기 전에 고정해, 달라진 환경에서 어떤 입력과 확률이 실패하는지 평가하는 설계입니다. **설계 단계이며 실제 포스트시즌 예측·수집·자동 실행은 시작하지 않았습니다.**

[발전 방향](development-roadmap.md) · [실험 기록 양식](experiment-log.md) · [시리즈 합성 예제](series-scenarios.md)

## 먼저 확정할 자료 조건

2026-03-27 [대회 정책](https://statiz.co.kr/board/?b_code=10000&b_idx=4294959131&m=main&mode=view)은 대회를 정규시즌으로 정하고 제공 데이터의 목적 외 사용을 제한합니다. **대회에 제출하지 않는다는 이유만으로 종료 후 데이터·API·학습 산출물의 사용 범위가 넓어지는 것은 아닙니다.** 보존 의무와 새 용도 이용도 구분합니다.

시작 조건은 후속 자체 연구에 사용할 원천 자료, API 접근, 기존 학습 모델의 이용 범위를 확인하는 것입니다. 확인한 조건을 내부 기록에 연결합니다. 확인 전에는 독립 합성 입력으로 수집·계산·기록 형식을 검증할 수 있습니다. 별도 이용 조건을 갖춘 공개 자료로 다른 연구를 진행하는 방법도 [R7](development-roadmap.md)에 정리했습니다. 이번 작업에서 주최 측에 문의를 보내거나 새 운영 API를 호출하지 않았습니다.

## 연구 질문과 해석

주 질문은 “고정한 정규시즌 모델이 포스트시즌에서 단순 기준보다 어떤 확률 손실을 보이는가?”입니다. 선발 운용, 불펜 사용, 휴식일, 상위 팀만 남는 대진은 입력 분포가 달라질 수 있는 후보 이유입니다. 관측 차이를 포스트시즌 자체의 인과효과로 단정하지 않습니다.

포스트시즌은 같은 팀과 시리즈의 반복이며 한 시즌의 경기 수가 적습니다. 한 시즌만으로 안정적인 모델 순위·재보정 계수를 추정하려 하지 않습니다. 사전 기록의 완전성, 큰 오차의 조건, 정규시즌 입력 범위 밖 사례를 중심으로 보고합니다. 분포 변화 연구의 개념은 [WILDS](https://proceedings.mlr.press/v139/koh21a.html)를 참고하며, 그 연구가 KBO의 변화를 입증하는 것은 아닙니다.

## 실행 전에 등록할 항목

| 항목 | 등록할 내용 |
| --- | --- |
| 평가 시작 | 프로토콜과 모델을 고정한 시각 이후의 미시작 경기. 이미 끝난 경기는 회고 자료로 구분 |
| 평가 종료 | 사전에 선택한 전체 포스트시즌 또는 특정 시리즈 종료. 유리한 연승 구간에서 중단하지 않음 |
| 모델 | 허용된 동결 모델 1개와 사전에 정한 단순 기준. 학습 종료일·설정·아티팩트 해시 보존 |
| 단순 기준 | 50% 확률 기준과 과거 허용 학습 구간의 홈 승률 기준. 상위 시드 승자 선택은 별도 비교 |
| 생성 시점 | 모든 경기에서 같은 시점 규칙. 기본 후보는 시작 20분 전이며 실제 자료 지연과 계산 시간을 확인해 확정 |
| 입력 | 원천·누적 종료일·가용 시각·결측·선발 미확정 시 처리. 미래 라인업 사용 금지 |
| 주 지표 | 승패 확정 경기의 경기별 Brier와 단순 기준 대비 차이 |
| 보조 지표 | LogLoss, 적중 수/대상 수, 입력·예측 확보율, 확률 구간과 오류 사례 |
| 종료 후 판단 | 적용 가능한 조건·실패 조건·추가 자료 필요 여부. 소표본 차이만으로 모델 교체하지 않음 |

현재 표의 시점과 기준은 **등록 전 후보안**입니다. 실제 날짜·시간·자료 조건을 채워 변경 불가능한 버전으로 보존한 시점부터 사전 설계로 취급합니다. 결과를 본 뒤 프로토콜을 수정하면 새 실험 버전으로 분리합니다.

## 제출 대신 무엇을 기록할 것인가

한 행은 경기 × 모델 × 예측 시점입니다. 최소 항목은 `game_id`, `scheduled_start_at`, `generated_at`, `model_version`, `feature_snapshot_id`, `probability_home`, `forecast_kind`, `submission_status`, `missing_reason`입니다. 모든 시각에 시간대를 둡니다.

- `forecast_kind=prospective`: 경기 전에 고정한 예측. 실제 운영 예측과 결과에 연결합니다.
- `forecast_kind=retrospective`: 사후 재구성. 전향적 적중률에 합산하지 않습니다.
- `submission_status=not_applicable`: 제출 없는 연구. 접수율의 분모에서도 제외합니다.
- 경기 전 예측이 없으면 누락 사유를 남깁니다. 누락을 복구한 재실행은 원본을 덮어쓰지 않습니다.
- 로컬 해시는 파일 변경 여부를 대조하는 수단이며 작성 시각의 독립 증명은 아닙니다. 접근이 제한된 서버의 보관 시각·실행 로그 등도 함께 남깁니다.

기존 대회 채점 함수는 미제출을 실패로 처리합니다. 자체 평가에 그대로 적용해 모든 경기를 실패 처리하지 않습니다. 예정 경기 전체에서 출발해 예측 유무·진행 상태를 대조하고, 모델 손실의 분모와 기록 확보율의 분모를 따로 보고합니다.

## 무승부와 경기 방식

기존 모델은 승패 확정 경기를 학습한 이진 확률입니다. 이를 그대로 쓰는 경우 홈 승리 확률의 목표를 **무승부가 아니라는 조건하의 홈 승리 확률**로 명시합니다. 실제 무승부는 승패 손실 평가에서 제외하되 일정·기록 확보율에서는 사라지지 않도록 집계합니다.

홈 승리·무승부·원정 승리의 세 확률을 평가하려면 별도의 허용 자료와 추정·검증 설계가 필요합니다. 소수 포스트시즌 경기만으로 새 무승부 모델을 맞추지 않습니다.

[KBO 경기 운영 체제](https://m.koreabaseball.com/About/GameManage.aspx)는 와일드카드에서 4위 팀이 최대 두 경기 중 한 번 이기거나 비기면 진출하는 구조, 준플레이오프·플레이오프 3선승과 한국시리즈 4선승을 설명합니다. 따라서 와일드카드를 단순한 동등한 3전2선승으로 계산하지 않습니다. 실제 시리즈 예측으로 확장할 때는 당해 규정의 무승부·재편성·연장·홈 배정까지 추가 확인합니다.

## 평가 보고서의 최소 구성

1. 전체 예정·진행·승패·무승부·취소 경기와 사전 예측 확보 수를 대조합니다.
2. 같은 경기에서 모델과 기준의 손실을 비교하고 비교에서 빠진 경기를 밝힙니다.
3. 정규시즌 기준 구간과 포스트시즌의 입력 결측률·분위수·범위 밖 비율을 비교합니다.
4. 큰 확률 오차의 사례를 입력 문제, 이용 시각 문제, 모델 오류, 확인 불가로 분류합니다.
5. 시리즈별 결과와 표본 수를 보여주며 경기 간 의존성을 명시합니다. 시리즈가 몇 개뿐이면 재표집 구간도 불안정하다는 점을 밝히고, 해당 구간을 승격 판단의 확정 근거로 삼지 않습니다.
6. 모델 수정은 평가 종료 후 제안합니다. 중간 수정이 불가피하면 기존 모델의 평가와 새 버전의 평가를 분리합니다.

시리즈 진출 예측을 매 경기 갱신하더라도 같은 시리즈에서 나온 여러 확률을 독립적인 여러 시리즈의 성적으로 세지 않습니다. 시작 전 예측과 진행 중 갱신 예측을 다른 과제로 보고합니다.

완료 산출물은 사전 설계 버전, 경기 전 예측 원장, 입력 시점 증거, 동일 경기 비교표, 실패 사례와 다음 판단입니다. 새 정확도 수치나 우승팀 예측은 이 설계 문서에 미리 채우지 않습니다.
