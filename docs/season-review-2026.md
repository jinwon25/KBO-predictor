# 2026 시즌 참가 결과와 운영 회고

이 프로젝트는 확률 예측과 제출·결과 추적을 함께 운영한 4인 팀 작업입니다. 공개 참가 결과를 출처·조회 날짜와 함께 기록하고, 초반 수동 제출과 이후 서버 운영을 구분해 다음 연구의 출발점으로 삼습니다.

## 수동 제출과 원격 자동 운영

참가자의 회고에 따르면 대회 초반은 수동 제출이었고, 원격 서버 운영은 대회 시작 이후 도입됐습니다. 수동 제출 시기의 기록, 미제출을 실패로 계산하는 공식 평가, 이후 서버에 보존된 예측의 범위가 다를 수 있습니다. 원격 전환의 정확한 날짜와 초기 경기별 접수 원장 전체는 아직 대조되지 않았습니다.

운영 원장에 기록이 없다는 이유만으로 실제 대회에 제출하지 않았다고 단정하지 않습니다. 반대로 모델을 사후 재실행해 생성한 확률을 당시 제출값으로 보완하지도 않습니다. 초반 수동 제출을 포함한 전체 팀 기록과 자동 운영 구간의 모델 평가를 나눠 해석하는 것이 필요합니다.

[2026년 3월 27일 공식 정책](https://statiz.co.kr/board/?b_code=10000&b_idx=4294959131&m=main&mode=view)은 미제출을 실패로 계산하며 무승부·취소·DH 2차전을 제외합니다. 마감 전 마지막 접수 확률을 사용하고 정확히 50%이면 실패입니다. 이러한 판정 조건과 기록 범위 차이는 내부 대시보드 수치와 공식 페이지 수치가 다른 이유가 될 수 있지만, 차이 전체의 경기별 원인은 접수 원장 대조 전까지 확정하지 않습니다.

## 어떤 문제를 다뤘는가

| 문제 | 구현·점검한 접근 | 남은 과제 |

| 모델 변경과 성적 해석 | 모델 적용 기간·경기 수를 표시하고 같은 경기의 예측을 비교 | 후보 선택에 쓰지 않은 이후 기간에서 검증 |
| 입력 자료의 시점 | 경기 전 보존 입력과 사후 재구성을 구분해 점검 | 변수별 원천·누적 종료일·이용 가능 시각의 계약 고정 |
| 승률과 실제 결과 추적 | 확률·승자·점수·제출 상태·제외 조건을 분리 | 공식 분모와 보존 예측 분모의 일별 연결 |
| 재현성과 원본 보존 | 모델·입력·예측·접수·검증 산출물을 별도로 보관 | 입력이 덮어써지지 않는 스냅샷과 고정 평가 자료 유지 |

현재 서빙은 `predictor_v13`의 `pit_lgbm_v1` 모드이며 직접 확률 LightGBM을 사용합니다. 과거 스태킹 설계, 사후 재구성 점수, 실제 운영 예측을 같은 성능 기록으로 합치지 않습니다. 팀 전체의 공식 기록으로 특정 모델의 우월성이나 개인 기여율을 계산하지 않았습니다.

## 관측에서 판단으로 이어진 세 가지 사례

아래는 비공개 결산 산출물을 점검해 정리한 판단입니다. 공개본에서는 결론과 판단 절차를 설명하며, 내부 경기별 수치의 독립 재계산에는 별도 보존 자료가 필요합니다. [지표 대조 예제](evaluation-guide.md)는 같은 평가 원칙을 가상 사례로 검증할 수 있게 작성했습니다.

### 1. 예측 기록의 부재와 실제 미제출을 구분

**관측:** 공식 참가 기록, 보존 예측, 접수 영수증의 대상 기간과 경기 범위가 같지 않았습니다. 초기 수동 제출과 이후 자동 운영이 함께 있으며 일부 접수 증거의 확인이 남아 있습니다.

**판단과 처리:** 일정·예측·접수·결과를 대조하고, 복구하지 못한 원본 예측은 누락으로 남겼습니다. 사후 모델 실행으로 당시 확률을 채우지 않았고, 원장 미확인과 실제 미제출을 같은 상태로 확정하지 않았습니다.

**다음 조치:** 경기번호별로 최종 접수값과 시각을 연결하는 원장과 누락 감시를 우선합니다. 자동화의 효과를 주장하려면 도입 전후의 비교 가능한 대상·접수율·운영 시간을 추가로 측정해야 합니다. 이번 결산에서 시간 절감이나 미제출 감소의 인과효과를 계산하지 않았습니다.

### 2. 모델 변경의 효과는 같은 경기에서 평가

**관측:** 모델별 운영 기간이 달라 서로 다른 대진과 입력 환경에서 성적이 집계됩니다. 같은 경기에서 비교해도 관측된 차이의 불확실성이 남았습니다.

**판단과 처리:** 모델 이름별 평균 순위를 만드는 대신 동일 경기의 확률·적중 차이와 단순 기준을 비교했습니다. 관측된 순증만으로 안정적인 우월성을 확정하지 않았습니다. 팀별 표에서는 한 경기가 양 팀에 포함되므로 행 수를 독립 경기 수로 사용하지 않았습니다.

**다음 조치:** 기간·시리즈 의존성과 여러 후보를 비교한 영향을 포함해 평가하고, 이미 점검한 시즌은 새 연구의 개발 자료로 표시합니다. 후보와 평가 기간을 고정한 이후 검증이 필요합니다. [연구 계획 E4·E5](research-plan.md)

### 3. 입력 정의와 확률의 의미를 먼저 점검

**관측:** 과거 재구성 입력과 경기 전 보존 입력의 기본값·분포를 대조할 필요가 있었고, 일부 입력은 당시 시점의 원본 보존 여부를 따로 확인해야 했습니다. 선발투수의 비율은 원시 카운트와 표본 수 없이 해석하기 어렵습니다.

**판단과 처리:** 모델 복잡도를 늘리는 것보다 변수의 정의·분모·누적 종료일·가용 시각을 먼저 고정하도록 후속 실험 순서를 정했습니다. 입력 중요도를 인과효과로 해석하지 않았고, 사후 진단에서 얻은 보정값을 곧바로 새 성능 개선으로 제시하지 않았습니다.

**다음 조치:** 학습 구간에서만 추정한 투수 비율 수축과 낮은 자유도의 확률 보정을 별도 후보로 검증합니다. 확률 보정과 승자 선택의 효과는 각각 평가합니다. [연구 계획 E0–E3](research-plan.md)

## 결산의 완료 범위

| 영역 | 상태 | 남아 있는 조건 |
| --- | --- | --- |
| 시스템 운영과 시즌 회고 | 수행·기록 | 전체 시즌 자동 운영 시작일과 초기 접수 증거의 완전 대조는 미확정 |
| 원본 보존과 전달본 검사 | 로컬 백업·해시 검사 완료 | 파일 무결성은 원천 자료의 완전성 또는 주최 측 제출 접수를 뜻하지 않음 |
| 참가 성적 공개 | 2026-10-14 팀 페이지 표기 인용 | 최종 심사·수상 결과는 별도 확인 |
| 공개 실행 예제 | 독립 합성 자료로 실행 가능 | 실제 운영 모델 학습과 시즌 성능을 재현하지 않음 |
| 다음 연구 E0–E5 | 설계 | 새 학습·독립 최종 평가·성능 개선은 미완료 |
| 대회 사후 제출 | 완료 여부 미확인 | 최신 제출 공지와 실제 제출 접수증 대조 필요 |

결산은 결과를 설명하고 다음 연구 조건을 정리한 단계입니다. 사후 제출·수상 심사·후속 모델 검증까지 끝났다는 의미로 사용하지 않습니다.

## 연구에서 얻은 판단

시즌 점검은 모델의 크기보다 검증 단위와 입력 정의를 먼저 고정할 필요를 보여줬습니다. 과거 재구성의 기본값과 실전 입력의 정의가 다르면 학습 알고리즘을 교체해도 같은 의미의 변수를 학습했다고 보기 어렵습니다. 선발투수 비율은 원시 카운트·표본 크기를 함께 기록해야 하며, 시즌·구장·득점 환경의 차이는 시간 조건을 지킨 상대 지표 후보로 검토합니다.

확률 품질, 승자 선택, 제출 완결성을 각각 평가합니다. 확률 보정으로 확신의 정도를 바꾸는 것과 승자 판별의 개선은 서로 다른 실험입니다. 동일 경기 비교에서 관측한 차이에는 불확실성 구간을 붙이고, 팀별로 같은 경기를 두 번 포함한 집계를 독립 표본으로 취급하지 않습니다. 구체적인 가설·설계·기각 조건은 [다음 연구 계획](research-plan.md)에 있습니다.

## 확인 범위와 보존 원칙

이 문서에 수치로 재기재한 성적은 주최 측 공개 팀 페이지의 요약입니다. 내부 경기별 확률·원천 통계·실제 접수 원장·학습 아티팩트는 공개 저장소에 옮기지 않았습니다. 상세 내부 결산과 원본 산출물은 사후 검증을 위해 별도로 보존합니다.

이 저장소의 독립 합성 데모는 채점 경계와 화면 상태를 설명합니다. 가상 팀·가상 모델의 데모 점수를 실제 참가 성과에 더하지 않습니다. 운영 경로 전체의 규정 적합성, 별도 참가 서약·FAQ와 추가 공개 권한에 관한 확인 범위는 [데이터·공개 정책](data-policy.md)을 따릅니다.
