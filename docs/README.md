먼저 [모델링 구조](modeling.md) → [실제 예측 성능](prediction-performance.md) → [대시보드 분석 경로](dashboard-showcase.md) 순서로 읽으면 입력·모델·결과가 어떻게 이어지는지 파악할 수 있습니다.

## 먼저 이해할 용어

| 용어 | 이 프로젝트에서의 뜻 |
| --- | --- |
| 공식 페이지 표기 | 주최 측 참가 페이지의 조회 시점 기록. 최종 심사·수상 발표와 구별 |
| 내부 평가 | 보존 예측과 결과를 대조한 값. 전체 참가 기록과 분모가 다를 수 있음 |
| PIT | Point-in-time. 예측 시점 이전에 이용 가능한 자료로 입력을 구성하는 조건 |
| 사후 재구성 | 나중에 받은 자료로 과거 입력을 만든 것. 당시 원본과 구별 |
| Brier·LogLoss | 확률 예측의 오차 지표. 승자 적중률·접수율과 구별 |
| 접수 미확인 | 접수 여부를 확정할 증거가 부족한 상태. 미제출 확정과 구별 |
| T−30 | 예정된 경기 시작 30분 전의 예측 실행 목표 |
| 블록 재표집 | 같은 날짜나 기간의 경기를 묶어서 다시 뽑아 모델 차이의 변동을 점검하는 방법 |
| 합성 데이터 | 실제 경기·제출 기록에서 만들지 않은 독립 가상 예제 |

## 공개본의 읽기 기준

공식 대회 결과는 주최 측 페이지의 요약으로, 내부 예측 성능은 기간·분모가 명시된 집계 표와 차트로 설명합니다. 공개 코드의 합성 점수는 실제 팀 성적에 합산하지 않습니다. 실제 API 응답·경기별 원장·학습 가중치·인증정보·운영 서버 원본은 별도로 보존하며, 공개 예제 실행을 전체 모델 학습과 시즌 성능 재현으로 해석하지 않습니다.
