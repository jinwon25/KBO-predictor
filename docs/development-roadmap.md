# 다음 연구의 선택: 예측 정확도에서 운영 판단까지

2026-10-14에 기존 결산과 후속 실험 E0–E5를 바탕으로 발전 방향을 비교했습니다. 가장 먼저 할 일은 **평가 가능한 자료를 만들고, 정보를 기다리는 가치와 운영 비용을 측정하는 것**입니다. 포스트시즌은 정규시즌 모델의 적용 범위를 확인하는 별도 평가로 추진할 가치가 있습니다.

이 문서는 연구의 우선순위와 실행 조건을 정리합니다. 이후 보관 자료로 R0의 완료 경기 대조, R1·R6의 시간 감사, R2의 오류 구간 진단을 실행했습니다. [운영 기록 분석](operations-review.md)에 결과와 범위를 연결했습니다. 새 모델 학습과 실제 포스트시즌 평가는 미실행이며, [시리즈 시나리오](series-scenarios.md)는 독립 합성 계산입니다.

## 방향별 비교와 우선순위

우선순위는 기존 결산에서 확인한 문제, 결과를 검증할 수 있는 정도, 필요한 자료를 종합한 프로젝트 판단입니다. 채용 효과나 예상 성능을 점수로 추정하지 않았습니다.

| ID·우선순위 | 연구 질문 | 필요한 자료·방법 | 남길 산출물 | 보여주는 분석 역량 |
| --- | --- | --- | --- | --- |
| R0 · 최우선 | 어떤 기록이 빠지거나 서로 다르며 평가에 어떤 영향을 주는가? | 일정·예측·접수·결과 대조, 데이터마트, 오류 유형 분류 | 분모 대조표, 품질 규칙, 원인·수정·잔여 차이 보고서 | 데이터 모델링·SQL 집계·품질 관리 |
| R1 · 높음 | 경기 직전까지 기다리는 정보의 가치가 지연 위험보다 큰가? | 같은 경기의 여러 사전 시점 입력, 추론 시간·접수 여유 | 시점별 손실·커버리지·지연 비용 비교, 실행 시점 제안 | 비교 설계·운영 의사결정 |
| R2 · 높음 | 어떤 상황에서 모델을 덜 믿어야 하는가? | 입력 누락·분포, 예측 확신도, 선발 변경·표본 수별 오류 | 오류 지도, 감시 지표, 조치 기준 | 세그먼트 분석·불확실성 해석 |
| R3 · 조건부 높음 | 정규시즌 모델이 포스트시즌에서도 유효한가? | 이용이 허용된 경기 전 입력, 동결 모델, 사전 기록 | 전향적 예측 원장, 분포 변화·오류 사례 보고서 | 새로운 환경 검증·실험 관리 |
| R4 · 중간 | 경기 확률이 시리즈 진출과 예상 경기 수로 어떻게 연결되는가? | 차전별 확률과 경기 방식, 상태별 확률 계산 | 가정별 진출 확률·시리즈 길이·민감도 표 | 확률 모델링·시나리오 의사결정 |
| R5 · 높음, R0 이후 | 복잡한 모델·보정이 단순 기준보다 실제로 나은가? | 동일 날짜 분할, 기준 모델, 독립 보정 구간 | 비교·제거 실험, 채택·기각 이유 | 기준선 설정·검증·설명 |
| R6 · 중간 | 자동화가 어떤 업무를 얼마나 줄였는가? | 실행·접수 이벤트, 수동 개입 시간, 실패·복구 기록 | 처리시간·개입률·실패 원인 보고서 | 프로세스 분석·효과 측정 |
| R7 · 중간, 공개 재현 우선이면 상승 | 다른 사람이 원천부터 결과까지 재현할 수 있는가? | 이용 조건이 명시된 별도 공개 자료와 고정 버전 | 데이터 사전·실행 파이프라인·독립 검증 보고서 | 재현성·출처 관리·범용화 |

R5는 기존 E1–E4와 연결됩니다. 새 이름을 붙여 동일 실험을 추가 성과로 세지 않습니다. R0·R1·R2·R6은 보관 자료로 가능한 범위의 분석을 실행했고, 미관측 자료가 필요한 부분은 남아 있습니다. R3·R7은 설계·자료 검토 단계이며, R4는 **합성 계산 예제만 구현**된 상태입니다.

## R0 — 평가용 데이터마트와 품질 분석

이번에는 완료 경기의 일정 한 버전·보존 예측·접수 이벤트를 별도 SQLite 테이블로 만들고 기존 결산 집계와 대조했습니다. 실제 DB는 비공개로 보존하며 [공개 SQL 예제](operations-review.md)는 독립 합성 입력을 사용합니다. 아래는 일정 변경·모든 실행·입력 스냅샷까지 확장할 전체 설계이며, 전부 구축한 상태는 아닙니다. JSON 원장을 보존한 채 분석용 테이블을 별도로 만듭니다. SQL을 도입한다면 파일 형식 변경 자체보다 **중복 없는 분모와 검증 가능한 결합**을 목표로 합니다.

| 테이블 후보 | 한 행의 단위 | 중요한 검사 |
| --- | --- | --- |
| schedule | 일정 버전별 경기 | 경기번호·대진·시작 시각·취소·재편성 매핑 |
| prediction_run | 경기 × 모델 버전 × 생성 시각 | 경기 전 생성, 확률 단위, 입력 스냅샷 참조 |
| receipt_event | 한 번의 제출 응답 | 재시도 중복, 성공 여부, 마감 전 마지막 접수 |
| outcome | 결과 버전별 경기 | 완료·취소·무승부, 정정 이력 |
| feature_snapshot | 예측 실행별 입력 | 원천·누적 종료일·취득 시각·결측 사유 |

일정에서 출발해 예측·접수·결과를 왼쪽 결합합니다. 여러 접수 이벤트를 그대로 붙여 경기 수를 늘리지 않고, 접수 판정에 맞는 한 건을 선택한 뒤 결합합니다. 접수 미확인·대조 후 미접수 확인·기록 시작 전·제외 경기·결과 미확정을 다른 상태로 유지합니다.

완료 기준은 새 테이블이 생기는 것이 아니라 원장 대비 행 수·주요 집계가 일치하고, 차이가 나는 경기의 사유가 설명되는 것입니다. 입력의 정상 0과 미수집 기본값도 분리합니다. [지표 정의](evaluation-guide.md), [데이터 품질 프레임워크](https://www.gov.uk/government/publications/the-government-data-quality-framework/the-government-data-quality-framework)

## R1 — 예측 시점과 정보 가치

기존 T−30 실행은 API 라인업이 T−60∼T−30에 갱신되는 운영자 관측을 반영한 선택입니다. 같은 모델의 T−60·T−45·T−30 입력을 비교하는 후보 설계로 조정했습니다. T−30을 기준으로 유지하고, 양 팀 라인업 완전성과 접수까지의 처리 여유를 함께 봅니다. T−20 추가 관측은 별도 후보이며 기본 실행을 늦추지 않습니다. 실제 시점은 자료 조건·요청 제한·계산시간을 확인한 뒤 등록합니다. [관측 근거와 시간 감사](operations-review.md)

가설은 “후반 시점에 새로 확보된 라인업·선발 정보가 확률 오차를 줄이지만 처리 여유를 줄일 수 있다”입니다. 이미 확정된 최종 라인업을 과거 시점에 붙여 개선을 추정하지 않습니다. 해당 시점 입력이 보존되지 않았다면 과거의 효과는 미확인으로 남기고 앞으로 수집합니다.

- 모델을 고정하고 같은 경기의 시점별 Brier·LogLoss와 승자 변경을 비교합니다.
- 모든 시점이 있는 경기의 쌍 비교와 전체 대상의 시점별 기록 확보율을 함께 제시합니다. 입력이 빠진 경기를 조용히 제외하지 않습니다.
- 라인업 신규 확보 여부별 결과도 보되, 그 그룹 차이를 라인업의 인과효과로 확정하지 않습니다.
- 실행시간 p50·p95, 오류율, API 요청 수, 마감 여유를 측정합니다. 계산 지연으로 기록하지 못한 경기도 실패 원인에 포함합니다.
- 늦게 기다린 모델과 미리 실행한 모델의 차이를 보고, 일정한 여유 이전에 마지막 유효 예측을 확정하는 운영 정책을 검토합니다.

첫 산출물은 시점별 “확률 손실–기록 확보율–운영 여유” 비교표입니다. 데이터의 시점 조건과 미래 구간 평가를 유지하는 근거는 [Forecasting: Principles and Practice](https://otexts.com/fpp3/toolbox.html)의 시계열 교차검증 설명을 참고합니다.

## R2·R5 — 실패 원인, 확률 신뢰도와 모델 비교

보관 예측으로 현·이전 모델의 확률 차이 구간과 월별 쌍 비교를 실행하고, 날짜·7일·14일 묶음의 불확실성을 확인했습니다. 이는 이미 검토한 자료의 탐색적 진단이며, 개선 구간을 골라 모델 전환 규칙으로 채택하지 않았습니다. 다음 연구의 세그먼트는 결과를 보고 유리한 구간을 고르는 대신 검증 가능한 가설로 시작합니다. 예를 들어 선발 기록의 극소 표본, 선발 변경, 핵심 입력 결측, 예측 확신 구간을 먼저 고정합니다. 팀별 편차는 탐색 결과로 두고 기간·대진과 함께 해석합니다.

입력 분포 변화와 성능 저하는 별개의 신호입니다. 결측률·기본값 비율·분위수·기준 범위 밖 비율을 감시하고 결과가 확정된 뒤 손실·보정 변화와 연결합니다. 하나의 분포 지표가 임계값을 넘었다는 이유만으로 자동 재학습하지 않습니다. 경보 기준은 과거 기준 기간에서 정하고 오경보·미탐 비용을 함께 봅니다.

확신도별 적중률에는 표본 수와 구간을 붙입니다. 여러 구간을 비교했거나 같은 팀·시리즈가 반복된 점을 기록합니다. 소수 고확률 경기에서 크게 틀렸다는 사실만으로 보정 계수를 즉시 바꾸지 않습니다.

단순 기준 → 상대 지표 로지스틱 → 소형 트리 → 필요한 보정 순으로 비교하고, 투수·타선·팀 전력 입력 그룹을 하나씩 제거해 추가 정보의 가치를 검증합니다. 모델 중요도는 인과적 선수 기여가 아닙니다. [기존 실험 설계](research-plan.md), [WILDS의 분포 변화 연구](https://proceedings.mlr.press/v139/koh21a.html)

## R3·R4 — 포스트시즌을 별도의 평가 문제로 설계

포스트시즌은 참가 팀이 달라지고 단기전 운영을 하므로 정규시즌과 다른 환경일 수 있습니다. 실제 차이의 크기와 원인은 분석할 가설입니다. “큰 경기라 예측이 어렵다” 같은 결론부터 정하지 않습니다.

**R3는 예측을 경기 전에 고정해 새로운 환경에서 평가하는 연구**, **R4는 주어진 확률을 경기 방식에 따라 변환하는 계산**입니다. 둘은 다른 산출물이며 시리즈 계산이 정확하다고 경기 확률 모델까지 정확해지지는 않습니다.

[포스트시즌 프로토콜](postseason-protocol.md)에 제출 없는 평가의 기록 방식·무승부·소표본·자료 조건을 정했습니다. [합성 시리즈 분석](series-scenarios.md)은 실제 모델 없이 지금 실행할 수 있습니다.

## R6 — 자동화의 효과를 업무 지표로 측정

예측 성능 외에도 운영 담당자가 확인해야 할 수고와 실패를 측정할 수 있습니다. 첫 단계는 전후 효과를 주장하기보다 일관된 계측 기준을 만드는 것입니다.

| 지표 | 정의 후보 | 해석 조건 |
| --- | --- | --- |
| 수동 개입률 | 수동 조치가 필요했던 경기 / 운영 대상 경기 | “개입” 이벤트 정의와 원인 코드 고정 |
| 마감 전 접수 확인율 | 마감 전 성공 접수 증거가 있는 경기 / 제출 대상 경기 | 자체 평가에서는 적용하지 않음 |
| 처리 지연 | 입력 준비부터 확률 보존·접수 확인까지 걸린 시간 | 예측 계산과 네트워크 지연 분리 |
| 복구 시간 | 장애 탐지부터 정상 처리 확인까지 | 장애가 없었던 날은 복구 시간 0으로 평균내지 않음 |
| 실제 수작업 시간 | 운영자가 기록한 확인·수정 시간 | 추정 코드 줄 수나 자동 실행 횟수로 대체하지 않음 |

자동화 전후에는 대상 경기·시즌 구간·작업 난이도가 달라질 수 있으므로 단순 전후 차이는 기술 통계로 표시합니다. 비교 자료가 부족하면 “운영시간 절감”을 성과로 만들지 않고 다음 기간의 관측부터 시작합니다. [ML Test Score](https://research.google/pubs/the-ml-test-score-a-rubric-for-ml-production-readiness-and-technical-debt-reduction/)의 데이터·모델·운영 감시 관점을 참고합니다.

## R7 — 실제 자료까지 공개 재현할 수 있는 별도 연구

현재 공개본은 독립 합성 예제이므로 실제 모델 학습 과정을 다른 사람이 재현할 수 없습니다. 이 간격을 메우려면 출처와 이용 조건이 명확한 자료로 **별도 학습·별도 평가**를 하는 방향이 있습니다.

후보인 [Retrosheet](https://www.retrosheet.org/game.htm)는 정규시즌·포스트시즌 기록을 제공하며 [이용 안내](https://www.retrosheet.org/notice.txt)에 출처 표기 조건을 명시합니다. 채택 시 요구하는 고지 원문을 포함하고 파일 버전·다운로드 날짜·정정 여부·해시를 기록합니다. 이번 작업에서 자료 다운로드나 학습은 실행하지 않았습니다.

MLB 자료의 결과를 KBO 성능의 증거로 가져오지 않습니다. 역사 자료의 날짜 분할은 회고 검증이고, 이미 공개된 결과를 나중에 분리했다고 실제 경기 전 예측이 되지는 않습니다. 별도 파이프라인을 만든다면 원천별 스키마와 재현 방법의 일반성을 평가합니다. 대회 제한 자료·학습 가중치와 혼합하지 않습니다.

## 실행 순서와 완료 산출물

| 단계 | 실행할 일 | 끝났다고 판단할 근거 |
| --- | --- | --- |
| 1. 분석 기반 | R0 + E0: 분모·기록 상태·입력 정의 대조 | 원장과 집계 대조, 차이 목록, 품질 테스트, 재실행 명령 |
| 2. 작은 비교 연구 | R1 + R2 + R5: 시점·실패 조건·단순 모델 비교 | 가설별 같은 경기 비교표, 누락·표본 수, 실패한 후보 포함 |
| 3. 이후 경기 검증 | 이용 조건을 확인한 R3 또는 다음 정규시즌의 E5 | 평가 시작 전 고정한 후보와 종료 조건, 경기 전 기록, 종료 후 보고서 |
| 4. 설명과 활용 | R4 + R6: 시리즈 시나리오와 운영 업무 지표 | 가정별 민감도, 계산 검증, 실제 관측한 업무 지표 |
| 5. 공개 재현 확장 | R7: 독립 자료로 원천부터 재현 | 출처·조건·버전·날짜 분할·실행 결과가 연결된 공개 사례 |

포스트시즌의 경기 전 기록 기회가 열려 있고 이용 조건을 확인했다면, 1·2단계를 전부 끝내기 전이라도 **새 모델을 튜닝하지 않는 동결 평가**를 병행할 수 있습니다. 결과를 본 뒤 시작일을 소급하지 않습니다. 위 순서는 일정 예약이나 자동 수집 실행 지시가 아닙니다.

완료 경기 범위의 SQLite 대조·접수 여유·오류 구간 분석은 실행했습니다. 시점별 새 입력 수집·새 학습·실제 포스트시즌 추론·수동 업무시간 측정은 실행하지 않았습니다. 각 연구를 시작할 때 [실험 양식](experiment-log.md)에 기간·분모·비교 기준·종료 조건을 채우고 상태를 바꿉니다.

## 뒤로 미룰 방향

- 앙상블·딥러닝 후보 확대: 입력 정의와 단순 기준 검증 뒤에 검토합니다.
- 작은 포스트시즌 표본으로 별도 모델 학습: 우선 동결 평가와 오류 사례를 축적합니다.
- 선수 교체·선발 순서의 최적 전략 단정: 선택 편향과 경기 상태를 반영하는 별도 설계가 필요합니다.
- 자동 생성 해설·새 대시보드 확장: 먼저 해설할 수 있는 실제 검증 결과와 사용자의 판단 과제를 확보합니다.

각 연구의 최종 문서는 **문제 → 자료와 분모 → 비교 방법 → 관측 결과 → 내린 결정 → 남은 한계**를 연결합니다. 성능이 오르지 않아도 입력 오류를 찾아내거나 불필요한 복잡도를 기각한 근거가 남으면 완결된 분석 사례가 됩니다.
