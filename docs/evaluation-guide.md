# 지표 정의와 분모 대조: 예측 품질과 접수 증거

같은 경기 기록에서도 어떤 행을 분모에 넣는지에 따라 적중률이 달라집니다. 이 문서는 지표의 정의를 고정하고 독립 합성 9경기로 계산을 재현합니다. 실제 KBO 기록이나 내부 결산 수치를 재배포한 예제가 아닙니다.

## 분석 단위와 지표 정의

분석 단위는 **경기 하나**입니다. 경기번호는 유일해야 하며 재시도한 제출 횟수를 경기 수로 세지 않습니다. 아래 정의는 공개 예제의 계약입니다. 실제 결산에서는 공식 제외 대상과 대조 가능한 기록 범위를 먼저 확정해야 합니다.

| 지표 | 분자 또는 계산식 | 분모·대상 | 답할 수 있는 질문 |
| --- | --- | --- | --- |
| 보존 예측 적중률 | 반올림한 확률로 선택한 승자가 실제 승자와 같은 경기 수 | 채점 대상 중 경기 전 확률이 보존된 경기 | 보존된 예측의 방향은 얼마나 맞았는가? |
| 마감 전 접수 확인분 적중률 | 마감 전 접수된 확률의 적중 수 | 접수 증거를 확인한 유효 제출 경기 | 확인된 접수 부분집합에서는 얼마나 맞았는가? |
| 접수 확인 비율 | 마감 전 접수 증거가 있는 경기 수 | 채점 대상 전체 경기 | 전체 대상 중 접수를 입증한 비중은 얼마인가? |
| 대회식 전체 적중률 | 유효 접수 중 적중 수 | 채점 대상 전체 경기 | 미제출을 포함한 전체 성적은 무엇인가? |
| Brier | (홈 승리 확률 − 홈 승리 여부)²의 평균 | 이 예제에서는 보존 예측이 있는 채점 대상 | 확률의 오차는 어느 정도인가? |
| LogLoss | 실제 발생한 결과에 부여한 확률의 음의 자연로그 평균 | Brier와 같은 경기 | 틀린 결과에 과도한 확신을 부여했는가? |

Brier·LogLoss에는 0–1 확률을 사용하며 낮을수록 좋습니다. 이 예제는 소수 둘째 자리로 정규화한 제출 단위의 확률을 평가합니다. 항상 50%를 내는 기준은 Brier 0.25, LogLoss ln(2)입니다. 반면 대회식 승자 적중에서는 50.00%를 실패로 처리합니다. 확률 평가의 기준값과 제출 전략을 구분합니다.

Brier 감소에는 판별력과 보정의 변화가 함께 작용할 수 있으므로 보정 곡선·구간별 표본 수를 함께 봐야 합니다. [scikit-learn 확률 보정](https://scikit-learn.org/stable/modules/calibration.html)

## 독립 합성 9경기

모든 경기는 2030년 4월 1일의 가상 사례입니다. 시작 시각은 18:30, 예제 마감은 18:15입니다. A·B·C·G·H·I의 접수 시각은 18:00, D는 18:16입니다. 확률은 홈 승리 기준입니다.

| ID | 결과·대상 | 보존 확률 | 접수 증거 | 보존 예측 판정 | 대회식 판정 |
| --- | --- | ---: | --- | --- | --- |
| A | 홈 승리 | 60% | 마감 전 확인 | 적중 | 적중 |
| B | 원정 승리 | 60% | 마감 전 확인 | 실패 | 실패 |
| C | 홈 승리 | 50.001% → 50.00% | 마감 전 확인 | 중립·실패 | 실패 |
| D | 홈 승리 | 70% | 마감 후 확인 | 적중 | 실패 |
| E | 홈 승리 | 없음 | 원장 전체 대조로 미접수 확인 | 평가 불가 | 실패 |
| F | 홈 승리 | 80% | 원장 미확인 | 적중 | 미확인 |
| G | 무승부 | 60% | 마감 전 확인 | 제외 | 제외 |
| H | 취소 | 60% | 마감 전 확인 | 제외 | 제외 |
| I | 홈 승리·DH 2차전 | 60% | 마감 전 확인 | 제외 | 제외 |

`receipt_evidence=complete`는 접수 원장의 대조가 끝났다는 뜻이지 접수가 성공했다는 뜻이 아닙니다. E는 대조 후 미접수로 확인한 사례, F는 증거가 부족한 사례입니다. `received_at=None`이라는 값만으로 두 상태를 같게 처리하지 않습니다.

예제의 한 행에는 경기 전 보존 확률과 최종 접수 대조 결과가 들어 있습니다. 실제 운영에서 복수 접수가 있다면 마감 전 마지막 성공 접수와 그 확률을 먼저 확정해야 합니다. 이 작은 예제는 접수 이벤트 전체를 재구성하는 도구가 아닙니다.

## 실행 결과와 해석

저장소 루트에서 실행합니다. Python 표준 라이브러리만 사용하며 외부 조회·학습·제출은 없습니다.

```bash
python -m demo.metric_audit
```

```text
독립 합성 9경기 | 실제 참가 성적 아님
전체 9 / 채점 대상 6 / 제외 3
보존 예측 적중률: 3/5 = 60.00%
마감 전 접수 확인분 적중률: 1/3 = 33.33%
접수 확인 비율: 3/6 = 50.00%
보존 예측 Brier: 0.18000 / LogLoss: 0.54002
접수 미확인 1건: 대회식 적중률 확정 불가
접수 미확인에 따른 가능한 범위: 16.67% ~ 33.33% (신뢰구간 아님)
```

- **분모 대조:** 전체 9 = 채점 대상 6 + 제외 3. 대상 6 = 접수 확인 3 + 지연 1 + 미접수 확인 1 + 접수 미확인 1.
- **예측 평가:** A·B·C·D·F의 5경기에서 A·D·F가 적중합니다. Brier는 (0.16 + 0.36 + 0.25 + 0.09 + 0.04) / 5 = 0.18입니다.
- **접수 평가:** A·B·C만 마감 전 접수가 확인됐고 A만 적중했습니다. 예측이 맞은 D도 지연 제출로 전체 채점에서는 실패합니다.
- **증거의 한계:** F의 접수가 미확인이므로 전체 성적을 단일 값으로 확정하지 않습니다. 가능한 적중 수는 확인된 1개부터 최대 2개까지입니다. 이 범위는 미확인 접수 때문에 생기는 범위이며 통계적 95% 신뢰구간이 아닙니다.

접수 원장이 없다는 이유로 F를 실패로 채우면 1/6을 확정하게 됩니다. 반대로 저장된 80%가 실제로 접수됐다고 가정하면 2/6을 확정하게 됩니다. 두 계산 모두 접수 증거를 넘어섭니다. 예제는 F를 확인 대상으로 남깁니다.

9경기는 판정 차이를 설명하기 위해 만든 자료입니다. 60% 적중률이나 Brier 0.18로 모델의 일반화 성능·개선 효과를 주장할 수 없습니다.

## 같은 경기에서 모델을 비교하는 이유

모델 A가 상반기, 모델 B가 하반기에 운영됐다면 대진·입력 가용성·모델 선택 시점도 함께 달라집니다. 기간별 성적을 빼는 것만으로 모델 교체 효과를 추정하지 않습니다.

1. 두 모델 모두 경기 전 확률이 보존된 동일 경기 집합을 만듭니다.
2. 전체 평가 대상에서 비교 집합으로 빠진 경기 수와 사유를 기록합니다.
3. 경기별 적중·Brier·LogLoss 차이를 계산합니다.
4. 날짜·시리즈 의존성을 고려해 차이의 불확실성과 기간별 편차를 보고합니다.
5. 후보 선택에 사용한 자료를 표시하고, 회고 비교와 독립 평가를 구분합니다.

확률 지표와 접수 지표는 같은 보고서에 두되 각각의 대상 수를 유지합니다. 모델을 바꾼 전후의 차이나 자동화 도입 전후의 제출률만으로 인과효과를 확정하지 않습니다. 후보 선택에 따른 편향은 [Cawley·Talbot](https://www.jmlr.org/papers/v11/cawley10a.html)을 참고했으며, 실제 결산의 비교 범위는 [운영 기록 분석](operations-review.md)에 정리했습니다.

## 검증 범위와 출처

[테스트](../tests/test_metric_audit.py)는 분모 분해, 미확인 접수의 상태 전환, 빈 분모, 중복 경기, 모순된 접수 증거와 극단 확률을 검사합니다. 빈 분모는 0%로 표시하지 않습니다. 실제 결과에 0의 확률을 부여한 LogLoss는 무한대로 유지하고 임의로 작은 유한값으로 바꾸지 않습니다.

채점 가정은 [2026-03-27 대회 정책](https://statiz.co.kr/board/?b_code=10000&b_idx=4294959131&m=main&mode=view)의 기존 확인 내용과 [공개 정책](data-policy.md)을 따릅니다. 마감 정각 허용과 정확한 반올림 중간값 처리에는 데모의 명시적 가정이 있으며 주최 측 구현을 인증하지 않습니다.

자료의 완전성·유일성·일관성을 구분하는 구성은 [영국 정부 데이터 품질 프레임워크](https://www.gov.uk/government/publications/the-government-data-quality-framework/the-government-data-quality-framework)를 참고했습니다. 야구 지표의 정의와 예제 판정은 이 프로젝트에서 정한 적용 방식입니다.
